# جلسة — إدارة الإيميلات والاشتراكات

لوحة عربية خفيفة مبنية على Laravel 13 وPHP 8.3، مع استقبال البريد عبر Cloudflare Email Routing وWorker وQueues. لا تحتاج واجهة اللوحة إلى npm أو Vite؛ CSS وJavaScript محليان داخل `public`.

## التشغيل المحلي على Laragon

إذا مجلد `C:\laragon\www\jalsaha` يحتوي مشروعك الأولي، خذ نسخة منه أولًا ثم استنسخ المستودع في مجلد فارغ، أو انسخ ملفات المشروع مع الحفاظ على `.env` المحلي. لا تستبدل قاعدة بيانات عليها بيانات مهمة.

```powershell
git clone https://github.com/abedmq/jalsaha.git jalsaha
cd jalsaha
composer install
Copy-Item .env.example .env
php artisan key:generate
```

لـMySQL عدّل `.env` وأنشئ قاعدة `jalsaha` فارغة:

```dotenv
APP_URL=http://jalsaha.test
APP_LOCALE=ar
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=jalsaha
DB_USERNAME=root
DB_PASSWORD=
```

ثم:

```powershell
php artisan migrate
php artisan jalsaha:admin your-admin@example.com
php artisan serve
```

الأمر يطلب الاسم وكلمة المرور بشكل مخفي؛ لا يوجد حساب مدير أو كلمة مرور افتراضية. استخدم `http://127.0.0.1:8000/login` مع `artisan serve`، أو اضبط Document Root في Laragon إلى **`jalsaha/public`** ثم افتح `http://jalsaha.test/login`. اضبط `APP_URL` ليطابق العنوان الذي تستخدمه. SQLite مدعومة للتجربة؛ اترك `DB_CONNECTION=sqlite`، وأنشئ `database/database.sqlite` قبل `migrate`.

## الاستخدام

1. أضف الدومين وفعّله، ثم جهّز استقبال البريد في Cloudflare كما في القسم التالي.
2. أضف الخدمات ونطاقات المرسلين الفعلية لكل خدمة. لا تُستخرج أكواد من مرسل غير مصنف. يجب ألا تتداخل نطاقات المرسلين بين خدمتين.
3. ولّد إيميلًا واحدًا باسم محدد، أو حتى 100 عنوان عشوائي في العملية. حدد المستخدم المسؤول؛ المستخدم العادي يملك إيميلاته فقط.
4. أضف اشتراكًا للإيميل والخدمة وحدد البداية والنهاية. يسمح الإيميل بأكثر من خدمة. للتجديد مع حفظ التاريخ، أضف سجل اشتراك جديدًا؛ لا تغير تواريخ السجل القديم.
5. من تفاصيل الإيميل، افتح «عرض الكود» داخليًا، أو أصدر رابط عميل خاص بالاشتراك. الرابط يظهر مرة واحدة، مخزنًا كتجزئة فقط، ويمكن إلغاؤه. شاركه فقط مع العميل المقصود. يعرف العميل الإيميل ويُدخله في صفحة الرابط.
6. راجع البريد الوارد وسجل الربط والإحصائيات من اللوحة. التواريخ الإدارية معروضة بتوقيت UTC؛ صفحة العميل تعرض وقت وصول الكود بتوقيت جهازه.

الأدوار: المدير يصل للجميع، والمستخدم العادي يرى حساباته فقط. صلاحيات منفصلة للدومينات والخدمات والتوليد والاشتراكات وقراءة الرسائل وعرض الأكواد وروابط العملاء والمستخدمين. «قراءة الرسائل» تكشف بطبيعتها محتوى البريد بما فيه الأكواد الموجودة فيه؛ افصلها عند منح الوصول. صلاحيات إدارة الدومينات والخدمات تؤثر على بيانات مشتركة، فامنحها لمشرفين موثوقين. تعطيل المستخدم يمنع جلساته الداخلية، لكنه لا يلغي روابط العملاء الصادرة سابقًا؛ ألغها صراحةً عند الحاجة.

## قواعد الربط

- حجز واحد لكل إيميل، حتى بين خدماته المختلفة، بعملية تحديث شرطية داخل transaction وقفل صف في MySQL/InnoDB.
- الحد الأقصى 10 دقائق. عند أول عرض لكود، يصبح وقت فك الربط بعد 60 ثانية، مع احترام سقف الـ10 دقائق الأصلي.
- لا يُعرض إلا كود غير مطالب به، من الخدمة المحددة، وصل خلال آخر 60 ثانية. الوقت من لحظة استقبال Worker، وليس وقت وصول إعادة المحاولة إلى Laravel.
- الكود يبقى ظاهرًا للصفحة نفسها بعد فك الربط، ولا تحصل الصفحة القديمة على كود الجلسة التالية. إعادة الربط الناجحة تبدأ دورة عرض جديدة.
- الصفحة تستعلم كل 3 ثوانٍ. حالة الحجز الفعلية تعتمد على وقت السيرفر، فلا تحتاج cron لفك الحجز؛ أي محاولة جديدة تستعيد الحجز المنتهي مباشرة.
- تبقى الجلسة محفوظة في `sessionStorage` عند تحديث نفس التبويب. لا يُفك الحجز فور إغلاق الصفحة؛ ينتهي تلقائيًا ضمن المدة. من يملك توكن الجلسة يملك الوصول لكودها، لذلك لا تشارك توكنات الجلسة.
- الاستخراج يدعم أكوادًا رقمية 4–8 خانات مع عبارات تحقق عربية أو إنجليزية. رسائل الدخول برابط بدل كود أو صيغ جديدة تحتاج تعديل `app/Services/OtpExtractor.php` مع اختبار بعينة منزوعة البيانات الشخصية.

## إعداد Cloudflare

وجود DNS على Cloudflare وحده لا يعني أن البريد يصل إليها. يجب تفعيل **Email Routing** على كل دومين وتوجيه MX إليها؛ إذا تستقبل حاليًا عبر مزود آخر، راجع إعدادات البريد قبل نقل MX.

1. ضع Laravel على عنوان HTTPS عام. `jalsaha.test` و`localhost` لا يمكن الوصول إليهما من Cloudflare؛ للاختبار المحلي استخدم Cloudflare Tunnel إلى خادمك المحلي مع حماية مسارات الإدارة.
2. أضف الدومين في اللوحة، وفي Cloudflare فعّل Email Routing واتبع إعدادات DNS المطلوبة. وجّه **Catch-all → Send to a Worker** إلى Worker هذا المشروع، أو أضف قواعد للعناوين منفردة. Catch-all يسمح للعناوين المولّدة بالاستقبال دون إنشاء قاعدة لكل عنوان. Laravel يتجاهل العناوين التي لم تُسجل في اللوحة.
3. من مجلد `cloudflare`:

```powershell
npm install
npx wrangler login
npx wrangler queues create jalsaha-email
npx wrangler queues create jalsaha-email-failed
```

4. غيّر `WEBHOOK_URL` في `cloudflare/wrangler.toml` إلى `https://your-app.example/api/inbound-email`.
5. ولّد سرًا عشوائيًا مرة واحدة، مثلًا بـ`php -r "echo bin2hex(random_bytes(32));"`. ضعه في `.env` باسم `CLOUDFLARE_WEBHOOK_SECRET`، وفي Worker بالاسم `WEBHOOK_SECRET`:

```powershell
npx wrangler secret put WEBHOOK_SECRET
npm run deploy
```

6. ارجع إلى Cloudflare واختر Worker في قاعدة Catch-all لكل دومين، ثم أرسل رسالة اختبار إلى عنوان مسجل. سيظهر «آخر استقبال» في صفحة الدومينات بعد وصولها إلى Laravel؛ هذا مؤشر استقبال فعلي وليس تحققًا آليًا من DNS أو ملكية الدومين.

Worker يحلل MIME بـ`postal-mime`، ويتجاهل المرفقات، ويقبل رسائل بحجم أقصاه 1 MB ويحفظ أول 24,000 حرف من النص. يُدخل الرسالة أولًا في Queue بشكل منتظر قبل إكمال المعالجة. المستهلك يرسل JSON بتوقيع HMAC-SHA256 وطابع زمني؛ Laravel يرفض التوقيع الخاطئ أو الطلب الأقدم من 5 دقائق. تجزئة محتوى الرسالة والمستلم تمنع إدخال إعادة المحاولة مرتين. الوقت الأصلي محفوظ عند تأخر التسليم حتى لا يظهر كود قديم على أنه حديث.

Queues يعيد المحاولة حتى 5 مرات ثم يوجه إلى `jalsaha-email-failed`. راقب هذه الـQueue وأعد معالجة الرسائل بعد إصلاح السيرفر أو السر. التخزين السحابي في Queues يحتوي نص الرسالة مؤقتًا؛ نص الرسائل والأكواد في قاعدة Laravel مشفّر باستخدام `APP_KEY`. احفظ هذا المفتاح ونسخة قاعدة البيانات معًا للاستعادة.

تأكد من صلاحية خطة Cloudflare لاستخدام Queues وتكاليفها من لوحة حسابك قبل النشر. لا يتضمن المشروع مزامنة تلقائية للدومينات وقواعد Routing عبر API؛ إعداد Routing يتم من Cloudflare مرة لكل دومين.

## الاختبارات

```powershell
php artisan test
node --test cloudflare/test/delivery.test.js
```

الاختبارات تشمل الحجز الحصري، انتهاء الـ10 دقائق، فك الربط بعد عرض الكود، منع إعادة تسليم الكود، عزل المستخدمين والخدمات، صلاحيات المستخدمين، توقيع webhook، تكرار التسليم، تأخر Queue، تشفير المحتوى، وإلغاء روابط العملاء. GitHub Actions يشغّل اختبارات PHP وJavaScript وتنسيق Pint عند كل push. اختبارات Laravel الافتراضية تستخدم SQLite في الذاكرة؛ تحقق من اتصال MySQL محليًا قبل النشر. نشر Worker واستقبال بريد حي يحتاج إعداد حساب Cloudflare الفعلي.

## النشر

عيّن `APP_ENV=production` و`APP_DEBUG=false` و`APP_URL=https://...` و`SESSION_SECURE_COOKIE=true`، ثم شغّل `php artisan migrate --force` و`php artisan optimize`. وجّه الويب إلى `public` فقط. لا ترفع `.env` أو قاعدة البيانات أو الأسرار، ولا تفعل تسجيل أجسام طلبات webhook على الـreverse proxy. حدد سياسة احتفاظ بالرسائل ونسخ احتياطي حسب حاجتك؛ الحذف الدوري التلقائي غير مفعّل افتراضيًا.
